## 1. 当前产品策略

- 微信小程序“小糖本”是主要用户入口；用户已反馈小程序审核通过。
- 手机网页继续保留，但不作为本轮主要推广入口。
- 小程序定位为个人健康数据记录工具，保留游客浏览，不提供药房、售药、问诊、诊断或治疗功能。
- 管理后台及既有药房功能继续保留，与小程序用户界面分开。
- 本轮明确不做“旧网页账号与微信账号关联”，不自动合并账号或记录。
- 生产环境已有真实用户持续录入数据，不得执行生产 `seed`、`docker compose down -v` 或未备份的数据库替换。

## 2. 本轮完成的五项调整

1. **录入与首页显示一致**：手选餐一／餐二后，修改日期时间不会覆盖选择；常用时段优先显示，其余可展开。首页参考范围、状态色带及单位与记录时段、用户设置一致；最近记录明确显示日期。
2. **记录可修改、失败可重试**：历史记录支持修改血糖、血压、血脂、尿酸；未保存的新建内容在本机按账号保留最多 7 天。新建请求使用稳定请求号，失败重试不重复入库；已删除记录不会因重试复活。新增、修改、删除、恢复与日汇总保持事务一致。
3. **统计更清楚**：血糖支持全部／空腹／餐一／餐二；显示完整 7／30／90 天日均值及逐笔明细，缺测明确标出。血压同时展示收缩压与舒张压，血脂四项可单独查看；加载失败可重试。
4. **后台直接查用户与记录**：平台管理员登录后进入“用户与记录”，支持搜索昵称、用户 ID、管理员备注，查看注册时间、最近录入及 7／30 天和全部有效记录次数；详情可按四类指标查看数值。管理员备注不修改用户昵称。
5. **近 7 天大字图片**：“统计”和“我的”增加图片入口，按指标及血糖时段分组、完整分页，每张最多 8 条；支持预览、主动转发、保存相册。预览及转发不要求相册权限，仅保存相册时申请相关授权。

餐一／餐二继续使用用户现有餐后参考范围，没有新增医学诊断或个性化治疗建议。

## 4. 发布范围与顺序

本轮不能只更新小程序，需要同步更新 **后端 API、管理网页前端、小程序**。现有网页餐一／餐二映射也有改动，可随前端容器发布。

1. 审查改动并完成发布检查后提交、推送。按用户本次要求先更新服务器，再由用户验收和提交小程序。
2. 发布前先执行现有备份流程，保留上一版镜像；详见 [Docker 运维说明](DOCKER-OPERATIONS.md)。
3. 更新后端并确认新迁移 `20260905000000_record_reliability_admin_notes` 成功：新增管理员备注字段及防重复提交凭证表。现有 Docker API 入口会运行 `prisma migrate deploy`；不要用 `db push` 或 seed 代替生产迁移。
4. 更新管理网页前端，确认管理员权限、用户列表、记录详情及备注保存正常。
5. 微信后台核对隐私指引中“保存图片到相册”的用途，与小程序内隐私政策一致；拒绝相册权限不应影响记录、预览、转发。
6. 后端验证正常后，再上传小程序体验版并提交审核；旧客户端仍可使用不带请求号的记录接口。
