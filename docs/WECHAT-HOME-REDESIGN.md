# 小程序首页改版规格 · 长者友好版「状态总览 + 陪伴感」

> 状态：待实现（由其他 agent 执行）。实现完成后交回本会话评审，不要自行合并/发布。
> 范围：仅 `apps/wechat-miniprogram` 的首页（`pages/home`）。不改动 `apps/web`、`apps/console`、`apps/api`、`packages/*`。
> **目标用户是中老年慢病患者**（记录血糖/血压/血脂/尿酸的长期人群）。这份规格里的所有设计判断都以这个人群的认知/视觉/动作/情感特点为第一优先级，"好不好看"排在"看不看得懂、点不点得中、信不信得过"之后。§2 是本文件唯一权威版本，之前讨论过的"多环嵌套仪表盘 + 三列 Bento + 徽章横滑条"方案**已废弃，不要参考旧版思路**。
> 背景：现状是把 Web C 端 `mobile.css` 逐字翻译过来的纵向卡片堆叠（hero + 3 张 mcard），详见 `apps/wechat-miniprogram/pages/home/index.wxml` 现状实现与 `docs/screenshots/app-glucose-home.png` 截图。

## 1. 为什么要改，以及为什么是这个方向（不要在实现时丢掉这些判断依据）

现状问题：
1. 四张卡片视觉权重相同，用户扫一眼抓不住"今天该关注什么"。
2. "连续记录 N 天"这种正反馈权重太低。
3. 底部 tabbar 用纯文字符号图标（⌂ ☰ ↗ ◯），观感粗糙。
4. 页面从上到下是同一种卡片语言，没有主次层次。

面向中老年用户的心理学/可用性依据（这些是本次方向选择的**核心理由**，不是可选装饰）：
- **工作记忆随年龄下降**：需要用户先学一套图形语法再解码信息的设计（比如同心圆环"外圈=血糖"）对老年用户是额外负担，直接用"大图标+文字"表达状态，不需要学习成本。
- **老花眼与对比敏感度下降**：小字号、浅灰色辅助文字在中青年眼里没问题，中老年用户可能直接看不清，本次改版要求整体上调最低字号（见 §3）。
- **色觉衰退（尤其蓝紫色区分能力下降）**：任何状态判断不能只靠颜色，必须"图标/文字双重编码"。
- **手部精细动作/震颤在老年群体常见**：点击区域要比常规设计更大、间距更松，横向滑动手势尽量避免。
- **游戏化语言（徽章/成就）容易显得幼稚甚至冒犯**：慢病老年用户的核心驱动力是安全感和被关心感，不是打卡成就感，文案语气要走"陪伴/坚持"而不是"游戏化"。
- **信任感优先于新鲜感**：过于花哨、多彩、几何化的设计会削弱"这是一个医疗工具"的信任感，也会增加"是不是升级坏了/要重新学"的焦虑，所以保留现状已经验证过的深色高对比 hero 卡片风格，不整体推翻。

## 2. 页面结构（自上而下，这是本次改版的唯一权威结构）

### 2.1 顶部区

- 沿用现有 `.safe-navbar` + `.inline-drop` + "糖迹"，不改。
- 问候行：`{{greeting}}` + 日期/今日笔数，样式沿用现状 `.greet`。
- **坚持横幅**（替代原来角落里的小胶囊）：一条静态的、不需要横滑的横幅卡片，内容是"已经坚持记录 N 天了，家人会看到你的坚持，继续加油"这类**关心语气**的文案，不用"徽章/成就"这类游戏化措辞，不用奖杯/星星类图标（可以用 `ti-heart-handshake` 之类偏"陪伴"含义的图标）。背景色复用现有 `.streak` 规则的暖色（`#F5DDB7` 描边 / `#FFF4E3→#FFE9CB` 底 / `#B26A12` 文字），这是代码库里唯一允许的非五态语义暖色例外，不要新增同类色。

### 2.2 今日总览（四指标状态，替代原方案的嵌套环形）

- 一行 4 个大号圆形图标（建议单个不小于 96rpx，约 48px），达标状态用对勾图标 + 品牌绿底（复用 `var(--m-{metric}-soft)` 做底、`var(--m-{metric})` 做图标色，四个指标各自用自己的主色，不要统一成一个颜色），非达标状态（`hi`/`lo`/`dhigh`/`dlow`）用感叹号图标 + 对应指标的 soft 底色，无数据用灰色虚线圆 + 空图标。
- 每个圆形下方必须同时展示**指标名 + 状态文字**（"血糖 / 达标"、"血脂 / 偏高"），颜色不是唯一的状态编码方式——这是硬性要求，不是可选项。
- 点击任意一个图标跳转到对应指标统计页，行为与现有 `goStats` 一致。
- 不需要任何"填充比例/百分比"的视觉表达，只有"达标 / 不达标 / 无数据"三态图标，不要为了好看去发明模糊的百分比语义。

### 2.3 血糖大卡 + 两项辅助指标

- 血糖沿用现状 `.hero` 深色大卡片风格**不要换成白底极简风格**：大数字、高对比、目标范围文字说明。可以保留现状的 `.hero .gauge` 横条或简化成一行"目标范围 4.4-10.0 mmol/L"文字，两者选实现成本低的即可，不强制要求可视化进度条。
- 不做迷你趋势折线图（sparkline）。老年用户不需要"看趋势线"，需要"今天这个数正不正常"，加一条小折线图只会增加解码成本又挤占字号空间，本期不做，未来如果要做趋势展示应该做成独立的、字够大的统计页面，不要塞进首页小卡片里。
- 血压 + 尿酸两个指标做成**两列**（不是三列/不含血脂，血脂已经在 §2.2 总览里表达过状态），每个色块内文字字号不低于 §3 的最低字号要求，保留图标 + 指标名 + 数值，不需要 sub 说明文字（现状 mcard 的 `.sub` 参考文案可以省略，减少信息密度）。

### 2.4 浮岛式底部导航

- 保留"四周留白的浮岛胶囊"这个视觉调整（比贴边通栏更精致），但**必须放大点击区域、加大图标间距**，具体数值见 §3。
- 5 个入口全部**始终显示文字标签**（不是只有激活态才显示文字），现状 `.tab` 本来就是图标+文字常显，这版不能退步成"只有图标"。
- 中央记录按钮做成带白色描边的悬浮圆形，尺寸不小于 §3 规定的最低点击区域。
- 行为、跳转逻辑与现状完全一致（复用 `switchPage`），只改视觉。

## 3. 硬性规则：最低字号与点击区域（新增，必须严格遵守）

| 项目 | 最低要求 |
|---|---|
| 任何信息性文字（标签、说明、状态文字） | 不低于 24rpx，核心信息（指标名、数值单位）建议 26-28rpx |
| 首页出现的正文/小节标题 | 不低于 28rpx |
| 关键数字（血糖大数字等） | 沿用现状 `.hero .v` 108rpx，不要缩小 |
| 任意可点击元素（tab、图标按钮、卡片） | 点击热区不小于 96rpx × 96rpx（约 48×48px），中央记录按钮不小于 108rpx |
| 相邻可点击元素间距 | 不小于 16rpx，避免误触 |
| 状态编码 | 颜色 + 图标 + 文字三选二以上同时存在，不允许仅靠颜色区分状态 |
| 手势交互 | 首页不出现依赖横滑/长按等非点击手势才能获取信息的交互（比如横滑徽章条），本版已经通过"静态横幅"规避 |

如果实现方发现现有全局样式（`app.wxss` 里其它页面复用的 class，比如 `.tab`、`.pill`）字号低于这个标准，**本期只需要保证首页新增/改动的部分达标**，不需要顺手把其它页面也翻一遍——那是后续统一收敛的工作，见 §10 非目标。

## 4. 状态优先级

- §2.2 的总览图标已经承担了"哪个指标不对劲"的一眼扫视功能，§2.3 的血压/尿酸色块**不需要**再叠加额外的强调标记，保持现状的 pill/文字状态表达即可，避免同一信息重复设计出两套视觉语言。
- 血糖 hero 卡片本身已经是全页面视觉权重最高的元素，不需要额外突出处理。

## 5. Token 使用规则（硬约束）

沿用 `docs/GOAL.md` §1.4 的铁律：**新增样式必须基于既有 `app.wxss` 里 `page{}` 已声明的 CSS 变量，颜色只能引用 `var(--*)`，禁止出现任何新的裸色值**。

| 用途 | 复用的现有变量 |
|---|---|
| 总览图标底色/图标色（达标态） | `var(--m-glucose{,-soft})` / `var(--m-bp{,-soft})` / `var(--m-lipid{,-soft})` / `var(--m-uric{,-soft})` |
| 总览图标（非达标态） | 对应指标的 soft 底 + `var(--hi)`/`var(--danger)` 系图标色，按 `utils/metrics.js` 现有 `statusColor` 映射，不要自造新映射 |
| 坚持横幅 | 已存在的 `.streak` 规则（`#F5DDB7` / `#FFF4E3→#FFE9CB` / `#B26A12`，历史遗留的唯一例外色） |
| 浮岛导航描边/底色 | `var(--line)` / `#fff` |
| 五态文案色 | `statusColor`（`utils/metrics.js` 已有） |

如果实现过程中确实绕不开需要新色值，先在 PR 描述里说明理由，比照 `docs/STYLE-DIFF.md` 的记录习惯写清楚，不要直接加裸色值糊过去。

## 6. 数据 / 逻辑要求

### 6.1 总览图标状态判定

对每个指标：
- 无 `latest` 记录 → 灰色虚线圆 + 空图标，文字显示"未记录"。
- `latest.status.key === 'ok'` → 达标态（对勾图标）。
- 其它 key（`hi`/`lo`/`dhigh`/`dlow`） → 非达标态（感叹号图标），文字直接用 `status.label`（现有值，如"偏高""偏低""显著偏高"），不要自己改写文案。

这是唯一需要的新计算逻辑，比原方案的环形填充比例简单很多，不需要额外接口调用。

### 6.2 空状态

用户一条记录都没有时（`overview` 四个指标全部 `empty`），整个"今日总览"区域降级为现状首页的"还没有记录，点下方水滴按钮记下第一条"引导文案，不展示 4 个空图标——空图标会显得像加载出错，体验比现状更差。

## 7. 技术实现要点（比原方案简单很多，因为不再需要环形图形）

1. **图标方案**：现状 `app.wxss` 全是文字符号图标，没有引入图标字体。这版需要"对勾/感叹号/心形/首页/历史/统计/我的/水滴"等一组统一图标。实现前选定一种小程序可行方案（本地 `iconfont.wxss` + unicode，或雪碧图/PNG 图标集），选型和引入方式记在 PR 描述里。不需要 `<svg>` 或 `canvas`，普通图标字体/图片即可，比原方案的环形渲染技术风险低得多。
2. **浮岛导航的安全区适配**：现状 `.tabbar` 已经处理了 `env(safe-area-inset-bottom)`（参考 `record-actions` 的写法），浮岛化之后底部留白结构变了，务必重新核对全面屏机型下导航条不会被系统手势条遮挡，且不要贴得太死导致点击区域被裁切。
3. **不要引入运行时依赖**：延续 `docs/SPEC.md` §2 的约束，不允许为了实现图标引入 npm 包 SDK，全部用小程序原生能力（WXML/WXSS + 本地图标资源）手写。
4. **既有测试约束**：`apps/wechat-miniprogram/test/structure.test.ts` 里有断言要求 `pages/home/index.wxml` 包含 `hero`、`mcard` 字样，且 `app.wxss` 包含 `.hero`、`.mcard` 选择器（见该文件第 83-98 行）。本方案保留了 `.hero`（血糖大卡片）；血压/尿酸两列如果继续复用 `.mcard` 类名（哪怕视觉上改窄改简），可以直接满足现有测试不用改测试文件——**优先这么做**。如果确实需要换成新类名，必须同步更新 `structure.test.ts` 里对应断言，并在 PR 里说明改动原因，不要让测试变红却不处理。

## 9. 合规红线（继承 `docs/SPEC.md`，不可妥协）

- 总览图标/横幅/文案中不得出现疾病诊断名词（"糖尿病""高血压 X 级""高脂血症""痛风"等），状态描述只能用"达标/偏低/偏高/显著偏高/边缘升高"这类已有词汇，直接复用 `status.label`，不要自己写新文案。
- 不新增任何诊断结论或用药建议类文案。
- 数值状态颜色仍然只能来自现有五态映射，不要为了"更好看"给数值本身换配色。

## 10. 非目标（本期不做，不要顺手做）

- 不做"家人可见/家属订阅提醒"这类社交功能——这是很有价值的方向（对老年用户的情感驱动力很对口），但涉及新的后端数据模型和权限设计，超出"首页视觉改版"的范围，留作后续单独立项。
- 不做全站字号审计——本期只保证首页新增/改动部分达到 §3 标准，其它页面留到后续统一收敛。
- 不做"大字模式/无障碍设置开关"——本期直接把默认字号和点击区域按老年友好标准做，不需要额外做一个可切换的模式。
- 不做血糖趋势可视化——见 §2.3，明确排除。

## 11. 验收标准（评审时会逐条对照）

- [ ] 血糖卡片保留深色高对比大数字风格，没有换成白底极简风格。
- [ ] 首页没有需要横滑/长按才能获取信息的交互。
- [ ] 坚持横幅文案是"陪伴/坚持"语气，没有"徽章""成就""解锁"这类游戏化措辞。
- [ ] 所有新增文字字号、可点击区域尺寸符合 §3 的最低标准（可以让实现方在 PR 里贴关键元素的 rpx 数值自查）。
- [ ] 底部导航 5 个入口点击行为、路由和现状完全一致，且始终显示文字标签。
- [ ] 浮岛导航在真机全面屏机型下不遮挡系统手势区域，点击区域没有被裁切。
- [ ] 全部新样式的颜色值可以在 `app.wxss` 现有变量表或 `.streak` 例外里找到出处。

- [ ] 未引入新的 npm 运行时依赖，未改动 `apps/api`/`apps/web`/`apps/console`/`packages/*`。
